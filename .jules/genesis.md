## 2023-10-27 — Local AI Analysis API Resilience added
**Failure point found:** The `ollama_deep_scan` function in `backend/services/ollama_scan.py` was making unprotected, synchronous HTTP POST requests to a local AI endpoint (`http://localhost:11434/api/generate`) with a hardcoded timeout, lacking retries for transient failures or a circuit breaker for persistent outages.
**Why it existed:** It was likely implemented as a rapid integration for local testing, assuming the local AI endpoint would always be available or that a single failure and fallback was acceptable behavior.
**Recovery built:** Created `backend/core/resilience.py` containing custom `CircuitBreaker` and exponential backoff retry decorators (`with_retry_sync`, `with_retry`). Refactored `ollama_deep_scan` to use a globally scoped helper function (`_do_ollama_request`) wrapped with `@cb` (CircuitBreaker) and `@with_retry_sync(max_attempts=3, base_delay=0.1)`. This ensures transient failures are retried automatically, and persistent failures trip the circuit breaker, failing fast and preventing system hang.
**Blast radius before:** Any transient glitch with the local Ollama service would immediately cause the scan to fail and fallback, degrading the threat detection quality for that user. Persistent failures would block the thread for up to 30 seconds (timeout) per request before failing, potentially exhausting server resources.
**Watch for:** Other unprotected external HTTP calls (e.g., `requests.get`, `requests.post`) in `backend/services/ai_deep_scan.py`, `backend/services/openclaw_agent.py`, or database calls that lack resilience mechanisms.
