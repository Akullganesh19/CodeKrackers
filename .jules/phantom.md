## 2025-06-30 — Frontend Phantom Fetch Request Coalescing
**Gap found:** Naive `fetch` calls in components across the application. Many dashboard widgets and components were independently polling or fetching the same endpoints (e.g., `dashboard-summary`, `threat_map`), causing redundant network traffic and unnecessary blocking rendering for repeat visits.
**Why it existed:** The app grew quickly, relying on the native `fetch` API inside `useEffect` without any centralized request manager, caching, or deduplication layer.
**Built:** Created `phantomFetch` in `app/lib/fetch.ts` to replace native `GET` fetch calls. This invisible infrastructure implements request coalescing (deduplication of simultaneous identical requests), Stale-While-Revalidate caching for instantaneous UI updates with background syncing, and an LRU cache with a maximum capacity to prevent unbounded memory growth. It also gracefully degrades to a 503 response if the network fails.
**Hot path affected:** Polling on `/dashboard`, initial load of `/analytics`, and data rendering for widgets in `/sms-scanner` (`AdminDashboard`, `ScammerMap`, `Sidebar`).
**Measurable improvement:** Significantly reduced the number of outbound network requests on pages with multiple components consuming the same APIs. Instantaneous navigation and rerendering for already-cached endpoints while staying fresh in the background.
**Next opportunity:** Investigate implementing an asynchronous task queue or retry mechanism for critical POST actions (e.g., submitting blacklist reports) to ensure eventual consistency if the server or network drops momentarily.
