## 2024-10-27 — Request Coalescing Added
**Gap found:** Multiple components in the Next.js frontend were independently making duplicate `fetch` calls to the same backend endpoints (e.g., `/api/analytics/dashboard-summary`, `/api/analytics/threat_map`, `/api/blacklist/report`). No request deduplication existed, leading to redundant network overhead and unnecessary backend load.
**Why it existed:** Components were developed in isolation and naively fetched the data they needed upon mounting, assuming the browser or framework would handle deduplication implicitly (which it doesn't always do for standard client-side `fetch` calls without Next.js caching layers).
**Built:** An intelligent Request Coalescing layer in `utils/api-client.ts` that intercepts outgoing `GET` requests. It maintains an `inFlight` Map of active promises keyed by URL and Authorization headers. If multiple components request the same resource simultaneously, it returns a clone of the existing in-flight promise rather than opening a new network connection.
**Hot path affected:** Page loads across the frontend, specifically `Dashboard`, `Analytics`, `SMS Scanner`, and `Call Monitor` pages which all hit analytics endpoints on mount.
**Measurable improvement:** Reduces the number of redundant API requests to identical endpoints occurring simultaneously, saving bandwidth, reducing backend load, and lowering the total wait time for the slowest components.
**Next opportunity:** Implement a stale-while-revalidate caching layer for relatively static configuration data or user profiles to avoid hitting the backend entirely on subsequent navigations.
