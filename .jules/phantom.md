## 2025-05-18 — Invisible Fetch Caching & Coalescing

**Gap found:** The frontend utilized naive native `fetch` calls for polling APIs (e.g., `setInterval` for the `/api/analytics/dashboard-summary`) and component mount logic (e.g., `/api/analytics/safety-score` in `Sidebar`). Multiple components rendering on the same page could trigger identical redundant API requests simultaneously, lacking deduplication. Furthermore, there was no caching strategy, forcing users to wait for full network round-trips for non-mutating idempotent requests on every render.
**Why it existed:** Native `fetch` lacks built-in caching, stale-while-revalidate (SWR) logic, request coalescing, and retries. Relying purely on it without a wrapper represents a rapid but naive development approach often found in early stages.
**Built:** Implemented `phantomFetch` in `@/app/lib/fetch.ts`, an invisible fetch replacement that introduces:
1. **Request Coalescing:** Identical requests currently in-flight are deduplicated (awaiting the same Promise) via an `inFlight` Map to mitigate "thundering herd" problems during initial app load when multiple components request the same data.
2. **Transparent TTL Cache with SWR:** Data is cached by URL and Authorization header for a configurable TTL. Stale cache hits serve instantly but trigger a background revalidation, dramatically improving perceived latency.
3. **Exponential Backoff Retries:** Robust retry logic for 5xx errors built-in for idempotent requests.
**Hot path affected:** Integrated into the dashboard's `setInterval` polling for `/api/analytics/dashboard-summary` and the `Sidebar`'s mount fetch for `/api/analytics/safety-score`, both of which are executed extensively as users navigate the app.
**Measurable improvement:** Polling the dashboard and navigating between pages that render the `Sidebar` will now serve from cache instantly. We avoid overlapping simultaneous requests on initial hydration for safety-scores and prevent multiple duplicate API calls on rapid component unmount/remounts. Expected to reduce raw server API hits on idempotent data fetching significantly, resulting in sub-millisecond perceived UI latency.
**Next opportunity:** Expand `phantomFetch` usage to all idempotent requests app-wide and introduce a background `predictivePrefetcher` for routes users are likely to visit next based on hover intents.
