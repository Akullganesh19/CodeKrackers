## 2024-05-23 — [Request Coalescing via Global Fetch Interceptor]
**Gap found:** Multiple components in the dashboard and analytics pages (e.g. OpenClawStatus, Topbar, Sidebar, Dashboards) make independent requests to the same endpoints at identical times on mount, leading to duplicate network calls for the same data payload and wasting throughput.
**Why it existed:** Simple implementation where components fetch data independently on mount, likely introduced as the application grew and different components required the same data without shared state management or a unified data fetching cache mechanism like react-query.
**Built:** Created a `PhantomProvider` that patches `window.fetch` to intercept outgoing GET requests. If a request with the exact same URL and headers is already in-flight, it returns a clone of the existing response Promise. This ensures all duplicate concurrent requests yield a single network call. It properly bypasses Next.js internal requests, requests with `AbortSignal`s, and non-GET requests to prevent unintended side effects.
**Hot path affected:** Initial dashboard and analytics page loads across the frontend where numerous small components request status or summary data from the backend APIs simultaneously.
**Measurable improvement:** Reduces the number of initial API calls significantly, cutting network latency and lowering the load on both the client (bandwidth/connections) and the backend (processing duplicate requests).
**Next opportunity:** Edge caching for static reference data or stale-while-revalidate patterns for the analytics dashboard data.
