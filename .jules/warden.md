## 2026-05-08 — [Active Exposure: PII and OTP Leaks in Application Logs]
**Data traced:** User emails, E.164 phone numbers, and plaintext OTP codes.
**Exposure found:** Plaintext logs across multiple services (e.g., `backend/api/auth.py`, `backend/services/spam_shield.py`, `backend/api/users.py`, `backend/services/notifier.py`). Standard library `logging.getLogger` and `structlog.get_logger` were dumping raw PII such as `USER_CREATED email=user@example.com`, `SPAM_BLOCKED phone=+19876543210`, and `SECURITY: Generated OTP for user@example.com -> 123456`.
**Fix:** Created a centralized, irreversible PII redactor in `backend/core/pii_redactor.py` using regex substitution (requiring `+` prefix for phones to prevent stripping timestamps). Intercepted all standard library logging by attaching `PiiRedactingFilter` to all root handlers. For standard logging, arguments are deep-copied and redacted to prevent leaking via `%s` interpolation. For `structlog` data inside `backend/core/logger.py`, added a recursive `pii_redacting_processor` that constructs a new `event_dict` without mutating the application's actual data in memory, closing the in-place mutation bug.
**Coverage confirmed:** Ran custom tests confirming both standard library (`logging`) and structured logs (`structlog`) mask PII natively without modifying call sites. Verified strings like `test.user@example.com` become `t***r@example.com`, phones become `+1***8901`, and OTP codes become `******`. Also verified dictionary payloads passed to structlog and arguments passed to standard logging remain unmutated in application memory.
**Still exposed elsewhere:** Potential leaks to third-party services (e.g., SendGrid/Twilio API calls payload caching, database backups, or third party cloud integrations) are beyond the scope of this logging redaction and remain to be fully audited.
