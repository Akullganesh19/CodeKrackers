## 2026-05-08 — PII Logging Redaction
**Data traced:** Email addresses and Phone numbers.
**Exposure found:** Actively logged in plaintext across authentication flow (OTP requests via SMS/Email), user creation events, spam reporting, and scam reporting in files like `backend/api/auth.py`, `backend/api/users.py`, and `backend/api/spam.py`.
**Fix:** Created structural redaction at the root logging level in `backend/core/logger.py`. Implemented both a `structlog` processor (`redact_pii_processor`) for structured logs and a `logging.Filter` (`PIIFilter`) for standard library logs attached directly to root handlers. Both employ recursive obfuscation rules to mask complete values down to `j***@gmail.com` and `***-***-1234`, preserving functional utility while securing PII.
**Coverage confirmed:** Manually tested standard logger and structlog locally with strings containing full PII data to verify successful recursive redaction. Run backend test suite to ensure the filter application didn't introduce type errors with complex logged payloads.
**Still exposed elsewhere:** Potential leaks could persist in exception traces if variables explicitly bind PII, or deep inside analytics/third-party API payloads exported externally (e.g. `Twilio`, `SendGrid`). These external integrations currently receive unredacted values, which is necessary for functionality, but access controls and data retention of those 3rd parties remain unverified.
