## 2026-07-04 — Implement Structural PII Redaction in Logs
**Data traced:** PII including `phone`, `otp`, `ssn`, `password`, `email`, `address`, `dob`, `card_number`, `phone_number` and matching string patterns.
**Exposure found:** Currently, PII flows unredacted into application logs directly from the backend modules (e.g., Auth service logs OTP and identifier info in plaintext `logger.info(f"SECURITY: Generated OTP for {otp_in.identifier} -> {otp_code}")`).
**Fix:** Modified the central `structlog` configuration in `backend/core/logger.py` to add a new `redact_pii` processor at the end of the processor chain. This traverses event dictionaries dynamically replacing matched keys with `[REDACTED]` and masks raw text strings matching email, phone numbers and OTPs using regex. The FastAPI application entrypoint `backend/main.py` is configured to trigger this logging config immediately, and all legacy `logging.getLogger` instantiations were updated to use the structured `get_logger` to guarantee compliance.
**Coverage confirmed:** Tested the `redact_pii` structlog processor in isolation ensuring the regex and recursive dictionary traversal effectively masks PII payload variables and log messages. Also verified via Python standard imports.
**Still exposed elsewhere:** Potential third-party integration points like Sendgrid API or Twilio API, which may log on their end (though not in VSDP codebase logs directly).
