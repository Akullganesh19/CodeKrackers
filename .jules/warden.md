## 2025-05-08 — PII Leakage in Application Logs
**Data traced:** PII (phone numbers, email addresses, OTPs, SSNs, passwords, card numbers)
**Exposure found:** Plaintext leakage in application logs (`backend/core/logger.py` formatting pipeline) across various endpoints and services like `backend/api/users.py`, `backend/api/spam.py`, and `backend/services/notifier.py` (e.g. `logger.info("USER_CREATED email=%s ...", ...)`).
**Fix:** Created and injected a custom recursive `redact_pii` processor in `backend/core/logger.py` within the `structlog` pipeline. The processor successfully redacts structured dictionary keys and employs contextual regex (`phone=`, `email=`, `to `) to mask strings, ensuring context is preserved while sensitive tokens are masked as `[REDACTED]`. The processor is positioned after stack info formatters to prevent PII leakage within stack traces.
**Coverage confirmed:** Manually tested the custom processor and regex redaction logic via custom scripts to ensure recursive structure traversal works and strict word boundaries are honored to prevent accidental partial substring matches. Verified module loading with zero `flake8` errors.
**Still exposed elsewhere:** Potential exports, analytics endpoints, or raw database dumps may still retain PII in original formats. The exact mechanism by which logs are piped into centralized aggregators (if any) could still hold un-redacted historical data.
