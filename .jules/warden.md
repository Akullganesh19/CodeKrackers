## 2026-05-08 — PII leaked in plaintext logs
**Data traced:** PII (Emails, Phone Numbers, OTP codes)
**Exposure found:** Plaintext logs (e.g., app logs in `logs/` directory) and potentially third-party logging providers. Logged via kwargs or directly in event messages (like `USER_CREATED email=...` or `OTP for user@example.com -> 123456`).
**Fix:** Added a custom `structlog` processor `redact_sensitive_data` to `backend/core/logger.py`. The processor dynamically masks emails, phone numbers, and OTPs in the event string and redacts kwargs based on sensitive keys (email, phone, password, otp, etc.).
**Coverage confirmed:** Verified the processor successfully redacts emails, phones, and OTPs in event messages and kwargs through a test script. Logs generated by `setup_logging` now output masked values (e.g., `j***@gmail.com`).
**Still exposed elsewhere:** Potential exposures in DB exports (like `/threats/csv` which exports source numbers) or analytics payloads not passing through structlog. Deletion paths are also not thoroughly verified.
